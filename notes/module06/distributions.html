Distributions.jl

Goal

  1. Become familiar with Distributions.jl as a package for flexible probabilistic simulation with probability distributions.
  2. Explore applications of simulation in statistics.

Overview

Distributions.jl implements a programming interface for working with probabilistic distributions.

  • This builds on the existing rand() function.
  • Provides several types to represent different probability distributions.
  • Additional interface for evaluating densities (PDFs), cumulative distribution functions (CDFs), log-likelihoods, moments, and other statistics.
  • Highly extensible: Provides advanced interface for controlling how sampling is carried out and algorithms for fitting distributions to data.

Random Variables

Suppose we want to sample 10 data points from \(\mathcal{N}(\mu, \sigma^{2})\). How is this done on a computer? In Julia, we first create a Normal object to represent target distribution. The following is equivalent to writing \(X \sim \mathcal{N}(0, 4)\)

rv = Normal(0, 2) # mean, standard deviation
Normal distribution
Parameters:
  μ = 0.0
  σ = 2.0

We can query the parameters of an instance of a distribution.

params(rv) # mean, standard deviation
(0.0, 2.0)

Certain moments are readily implemented and accessed with descriptive function names. For example, the mean can be recovered using

mean(rv)
0.0

Ditto for other quantities of interest:

var(rv)
4.0
median(rv)
0.0
quantile(rv, 0.25) # the 0.25 quantile
-1.3489795003921636
quantile(rv, 0.5) # same as median
0.0

Plotting

In the Plots.jl ecosystem, StatsPlots.jl implements recipes for plotting distributions. It is quite flexible, allowing users to plot PDFs, CDFs, and quantile-quantile (QQ) plots.

Mixtures

Suppose you have a finite collection of probability densities \(\{f_{i}(x)\}_{i=1}^{K}\). In general, the linear combination \(\sum_{i=1}^{K} f_{i}(x)\) does not define a probability density; that is, there is no guarantee that \[ \int_{-\infty}^{+\infty}~\sum_{i=1}^{K} f_{i}(x)~dx = 1. \] This can be amended if we replace the linear combination with a convex combination. Given weights \(p_{i} \ge 0\) such that \(\sum_{i=1}^{K} p_{i} = 1\), we define \[ h(x) = \sum_{i=1}^{K} p_{i} \cdot f_{i}(x). \] Using linearity of summation and integration, write \[ \int_{-\infty}^{+\infty}~\sum_{i=1}^{K} p_{i} \cdot f_{i}(x)~dx = \sum_{i=1}^{K} p_{i} = 1, \] where the last equality follows by definition of the \(p_{i}\). Finite mixture models and mixture distributions are versatile modeling tools in statistics and machine learning.

Mixture distributions are easy to work with through Distributions.jl.

X = MixtureModel(
  [Normal(-5.0, 1.0), Normal(0.0, 2.0), Normal(5.0, 1.0)],
  [0.25, 0.4, 0.35]
)

Examples

1. Multiple regression with IID errors

function simulate_reg_instance(n, p; noise = 1.0, seed = 206)
  # Simulation model
  σ = noise
  rng = Xoshiro(seed)
  X_dist = Uniform(-1, 1)
  b_dist = Beta()
  ϵ_dist = Normal(0, σ)

  # y = Xβ + ϵ
  X = rand(rng, X_dist, n, p)
  b = rand(rng, b_dist, 3)
  y = X*b + rand(rng, ϵ_dist, n)

  # Store simulation data in a NamedTuple
  ground_truth = (;
    nobs     = n,
    nvar     = p,
    noise,
    response = y,   noise_dist  = ϵ_dist,
    design   = X,   design_dist = X_dist, 
    coeff    = b,   coeff_dist  = b_dist,
  )

  return ground_truth
end

  • Since it is a simulated problem instance, we can record the ground truth.

n, p = 200, 3
gt = simulate_reg_instance(n, p; noise = 0.1)
y, X, b0 = gt.response, gt.design, gt.coeff;

We estimate \(\beta\) using least squares; i.e. we minimize \(\|y - X\beta\|_{2}^{2}\). Let’s compare the estimator derived using a QR decomposition against the result derived using a Cholesky decomposition. Mathematically, the choice of algorithm does not affect the result. Since the simulation conditions are “mild”, we do not anticipate numerical discrepancies.

Xt = transpose(X)
b_qr   = qr(X) \ y
b_chol = cholesky!(Symmetric(Xt * X)) \ (Xt * y)
3-element Vector{Float64}:

 0.5874305893881918
 0.8881651019617088

How well do we estimate \(\beta\) and predict \(y\)? We compare using the mean squared error and norm of residuals.

mse(x, y) = mean(abs2, x - y)

models = (b_qr, b_chol)
model_names = ("QR", "CHOL")

results = DataFrame()
for (b, name) in zip(models, model_names)
  yhat = X*b
  push!(results, (;
    algorithm = name,
    MSE_y = mse(y, yhat),
    MSE_b = mse(b0, b),
    rnorm = norm(y - yhat),
  ))
end

2. Correlated features

To benchmark a method in a scenario with correlated features/covariates, we can use a Multivariate Gaussian distribution. The Toeplitz covariance model is commonly used:

ρ = 0.25
Σ = [ρ ^ abs(i -j) for i in 1:p, j in 1:p]
3×3 Matrix{Float64}:
 1.0     0.25  0.0625
 0.25    1.0   0.25
 0.0625  0.25  1.0
  • This covariance matrix is 3 by 3 because we have 3 features/covariates.
  • If \(\rho = 0\) then \(\Sigma = I_{p \times p}\); reduces to IID features/covariates.
  • If \(\rho = 1\) then \(\Sigma = \boldsymbol{1} \boldsymbol{1}^{\top}\); not a proper covariance matrix! (Why? Check eigenvalues/positive definiteness).
function simulate_reg_correlated(n, p; noise = 1.0, corr = 0.0, seed = 206)
  # Simulation model
  σ = noise
  ρ = corr
  Σ = [ρ^abs(i - j) for i in 1:p, j in 1:p]
  rng = Xoshiro(seed)
  X_dist = MvNormal(zeros(p), Σ)
  b_dist = Beta()
  ϵ_dist = Normal(0, σ)

  # y = Xβ + ϵ
  X = rand(rng, X_dist, n) |> transpose # X_dist is trivariate; don't need p
  b = rand(rng, b_dist, p)
  y = X*b + rand(rng, ϵ_dist, n)

  # Store simulation data in a NamedTuple
  ground_truth = (;
    nobs     = n,
    nvar     = p,
    noise,
    corr,
    response = y,   noise_dist  = ϵ_dist,
    design   = X,   design_dist = X_dist, 
    coeff    = b,   coeff_dist  = b_dist,
  )

  return ground_truth
end

3. Kernel Density Estimation

In the univariate case, kernel density estimation seeks an estimate of a probability density given data. Assuming IID data, we can express the estimator of the unknown density \(f(x)\) as \[ \hat{f}(x) = \frac{1}{n} \sum_{i=1}^{n} \mathcal{K}_{h}(x, x_{i}), \] where \(\mathcal{K}_{h}(\cdot, \cdot)\) is a kernel and \(h\) is a bandwidth parameter to controls the degree of smoothing. From the mixture perspective, we can approximate the unknown density as \[ \hat{f}(x) = \sum_{i=1}^{n} \frac{1}{n} \cdot f(x \mid x_{i}, h), \] where each component has distribution \(\mathcal{N}(x_{i}, h)\) and weight \(n^{-1}\).

n = 100
dist = Laplace(10.0)
data = rand(Xoshiro(206), dist, n) # location = 10, scale = 1
plot(dist, xlims = (0, 20), title = "Laplace PDF")
function kde_example(data, h)
  n = length(data)
  fhat = MixtureModel(
    [Normal(x, sqrt(h)) for x in data],
    1 / n * ones(n)
  )

  xs = range(0, 20, length = 101)
  ys = pdf.(fhat, xs)
  return plot(xs, ys; title = "KDE with Gaussian basis (h = $(h))")
end
