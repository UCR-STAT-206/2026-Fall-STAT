Finite Differences

How can we compute derivatives on a computer?

  • This is a relatively simple problem, at least conceptually.
  • Unless we need to exploit structure (to design a good algorithm!), we don’t want to derive derivative functions by hand.

Recall that the gradient of \(f\) at \(\boldsymbol{x}\) is

\[ \nabla f(\boldsymbol{x}) = (D_{1}f(\boldsymbol{x}), \ldots, D_{d}f(\boldsymbol{x})), \]

so we only need a program to compute partial derivatives. One way is to simply exploit the definition of differentiation

\[ f^{\prime}(x) = \lim_{h \to 0} \frac{f(x + h) - f(x)}{h}, \]

by evaluating the RHS with a “small” \(h\). This is essentially the Finite Difference approach in the field of numerical differentiation. The FiniteDifferences.jl package in Julia implements various finite difference operators.

TipR Users

See numDeriv for finite difference methods in the language.

How well does this work in practice? Let’s look at \(f(x) = \cos(x)\)

xs = range(-2*pi, 2*pi, step = pi/32)
plot(xs, cos; lw = 3, label = "f(x) = cos(x)")
Dx = forward_fdm(2, 1) # first derivative, using 2 grid points; forward difference
Dx_cos(x) = Dx(cos, x) # evaluate derivative of cos at x
fig = plot(xs, Dx_cos; lw = 3, label = "Finite Difference")
plot!(xs, x -> -sin(x); lw = 3, ls = :dash, label = "f'(x)")
fig

The grid field indicates how \(f(x)\) is evaluated to approximate \(f^{\prime}(x)\); look ahead 1 step.

Dx

Change the function and the program still works!

Dx(x -> x^2, 10) # 20

But now the issue becomes apparent: These are just approximations. Central differences help but we’ll have to deal with both approximation error and floating point errors in our code.

Dx = central_fdm(5, 1) # first derivative, 5th order

The approximation error goes down at the cost of more function evaluations.

Dx(x -> x^2, 10) # 20

The Problem

Finite differences are widely used in scientific computing, especially ODEs/PDEs. Problems in this space often require higher order derivatives. More pressing, however, is that models in applications (be it scientific computing, statistics, or machine learning) are often complex systems unto themselves.

Thinking of models as computational graphs, it becomes apparent that complex models become unwieldy for differentiation; see this JAX blog from Google for an example. So setting approximation errors aside, the computational complexity of a “differentiation program” can limit the types of applications that can be addressed. You’re not going to handwrite any derivatives of a neural network, either.

Are there any alternatives to finite differences?

Automatic Differentiation

Automatic differentiation is a technique used to compute exact derivatives on computers, up to machine precision. It comes in many flavors, and many important machine learning packages are built on the idea of being able to evaluate derivatives of complex objects efficiently.

  • Autograd in Python; reverse-mode differenation (backpropagation)
  • ForwardDiff; forward-mode with dual numbers
  • Enzyme; forward/reverse-mode at LLVM level
  • Zygote; reverse-mode source-to-source
  • Symbolics; Computer Algebra System (CAS)
  • TaylorDiff; Taylor-mode AD similar to that which appeared in the JAX post above.

Dual Numbers

Before we look at AD let’s examine a curious extension of the real line \(\mathbb{R}\), the dual numbers. Dual numbers define a number system with infinitesimals \(\epsilon\) such that \(\epsilon^{2} = 0\) *by definition. Given a real number \(x\), one constructs its associated dual number by \(x + \epsilon\). The utility of dual numbers is that evaluating functions over dual numbers immediately yields function values and derivatives simultaneously. For example, consider \(f(x) = x^2\). Evaluation of \(f\) over dual numbers yields

\[ f(x + \epsilon) = (x + \epsilon)^2 = x^2 + 2x\epsilon + \epsilon^2 = x^{2} + 2x\epsilon = f(x) + f^{\prime}(x)\epsilon. \]

The real part of the dual number is simply the value \(f(x)\), whereas the dual part accumulates \(f^{\prime}(x)\). The technique generalizes to more complicated functions and extens to vector-valued functions in general. The ForwardDiff documentation has excellent explanations on the mathematical and implementation details.

This may sound too good to be true! Extensions of the real line using infinitesimals was formalized by the logician Abraham Robinson. Dual numbers and forward-mode AD are not merely curious computational tricks.

function rosenbrock(x)
  return (1 - x[1]) ^ 2 + 100 * (x[2] - x[1] ^ 2) ^ 2
end
xs = ys = range(-3, 3, length = 101)
tv = -4:4
tl = [L"10^{%$i}" for i in tv]
contourf(xs, ys, (x, y) -> log10(rosenbrock([x, y]));
  levels = 16,
  color = :plasma,
  xlabel = L"x_{1}",
  ylabel = L"x_{2}",
  colorbar_ticks = (tv, tl),
  title = "Rosenbrock Function"
)
ForwardDiff.gradient(rosenbrock, Float64[1, 1]) # gradient at minimum
