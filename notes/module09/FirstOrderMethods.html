Overview

One approach to solving an unconstrained optimization problem

\[ \min_{\boldsymbol{x}}~f(\boldsymbol{x}), \]

is to find \(\boldsymbol{x}_{\ast}\) such that the gradient vanishes; i.e. \(\nabla f(\boldsymbol{x}_{\ast}) = \boldsymbol{0}\). This requires that the optimization model \(f(\boldsymbol{x})\) is, at a minimum, once differentiable. We will refer to the condition above as a stationary condition, first-order condition, or necessary condition.

Hierarchy of Optimization Methods

  • Zero Order: Use only function values, \(f(\boldsymbol{x})\), to solve the problem. Used if \(f(\boldsymbol{x})\) does not have a sensible derivative or gradients are too costly to evaluate. Usually check \(|f(\boldsymbol{x}_{k}) - f(\boldsymbol{x}_{k+1})| < \epsilon\); i.e. function values have converged.

    • Nelder-Mead
    • Approximate Gradient Descent (i.e. using finite differences)
    • Random Coordinate Descent

  • First Order: Uses at most information from first derivatives, \(f(\boldsymbol{x})\); i.e. directions of ascent/descent. Usually check \(\|\nabla f(\boldsymbol{x}_{k+1})\| \le \epsilon\); i.e. gradient is sufficiently small.

    • Gradient Descent (for certain choices of step size)
    • Stochastic Gradient Descent (ditto)
    • Mirror Descent
    • ADMM (Alternating Direction Method of Multipliers)

Notion of derivative not limited to the “usual” definition; also covers subgradient and other weak notions of derivative.

  • Second Order: Uses at most information from second derivatives, \(d^{2}f(\boldsymbol{x})\); i.e. curvature.

    • Newton’s Method
    • Fisher Scoring
    • Coordinate Descent?

Common in scientific computing, even for “large” scale problems. Conspicuously absent in (deep) machine learning. Advances in randomized linear algebra may change this.

Gradient Descent

To minimize \(f(\boldsymbol{x})\), we construct a local linear model to approximate the objective function near our current estimate \(\boldsymbol{x}_{k+1}\):

\[ f(\boldsymbol{x}_{k} + \boldsymbol{d}) \approx f(\boldsymbol{x}_{k}) + df(\boldsymbol{x}_{k})\boldsymbol{d}, \]

where \(\boldsymbol{d}\) denotes the search direction. Think of the linear term as an inner product, \(\langle \nabla f(\boldsymbol{x}_{k}), \boldsymbol{d} \rangle\). We’d like for \(f(\boldsymbol{x}_{k} + \boldsymbol{d}) < f(\boldsymbol{x}_{k})\); that is, the update should be an improvement. That indicates that we should choose \(\boldsymbol{d}\) to make the linear term as negative as possible.

Unfortunately, this formulation is ill-defined. We only care about direction, not magnitude, so we formulate the search problem as

\[ \min_{\boldsymbol{d} : \|\boldsymbol{d}\| \le 1}~df(\boldsymbol{x}_{k}) \boldsymbol{d}, \]

which is a constrained minimization problem. We only need a unit vector to tell us the direction, then we can figure out how much to move in that direction. This is the method of steepest descent; we seek descent directions that move along the largest directional derivative.

  • If we take \(\|\cdot\|\) to mean the Euclidean norm, \(\|\cdot\|_{2}\), then one can show that the best search direction is \(\boldsymbol{d} \equiv -\nabla f(\boldsymbol{x}_{k})\) (unnormalized). This is the usual understanding of gradient descent.
  • Other choices lead to interesting results. Taking \(\|\cdot\|_{1}\) instead suggests \(\boldsymbol{d} \equiv - \frac{\partial f}{\partial x_{i}} \boldsymbol{e}_{i}\) where \(|\frac{\partial f}{\partial x_{i}}| = \max_{j} | \frac{\partial f}{\partial x_{j}} | = \|\nabla f(\boldsymbol{x})\|_{\infty}\). That is, we move in the direction with largest partial derivative. When applied to linear regression analysis, this happens to be forward stagewise regression!

Once we have a recipe for \(\boldsymbol{d}\), we update our estimates via the rule

\[ \boldsymbol{x}_{k+1} = \boldsymbol{x}_{k} + \boldsymbol{d}. \]

Naive Approach

The (naive) gradient descent approach is simply

\[ \boldsymbol{x}_{k+1} = \boldsymbol{x}_{k} - \nabla f(\boldsymbol{x}_{k}). \]

Without any restrictions on the gradient, it becomes possible for the method to overshoot and thus fail to converge, even when the underlying function is easy to minimize.

myfun(x) = (x - 1)^2

function gradient_descent_example(x0, t::Real = 1.0)
  x = x0
  history_x = [x0]
  for i in 1:10
    x = x - t * ForwardDiff.derivative(myfun, x)
    push!(history_x, x)
  end

  @show history_x

  fig = plot(range(-3, 4, step = 0.25), myfun, label = L"f(x)", lw = 3)
  plot!(history_x, myfun.(history_x), label = "History", lw = 3, ls = :dash)
  return fig
end

Fixed Step Size

Amend the gradient descent updates with a step size that indicates how far along to move in the direction \(\boldsymbol{d}\):

\[ \boldsymbol{x}_{k+1} = \boldsymbol{x}_{k} - t \nabla f(\boldsymbol{x}_{k}). \]

This changes little in determining \(\boldsymbol{d}\) if we are happy to simply take \(t\) to be a fixed value.

gradient_descent_example(3.0, 0.9)
gradient_descent_example(3.0, 0.5)

Why does the choice \(t = 0.5\) lead to an algorithm that converges in one step?

Line Searches

Once we’ve fixed the search direction \(\boldsymbol{d}\), we might, “How should we choose the step size, \(t\)?” This motivates the notion of line searches.

Exact

The exact line search problem is

\[ \min_{s,~s \ge 0}~f(\boldsymbol{x} + s \boldsymbol{d}), \]

where \(\boldsymbol{x}\) and \(\boldsymbol{d}\) are fixed beforehand. The goal is to have \(f(\boldsymbol{x} + s \boldsymbol{d}) < f(\boldsymbol{x})\). This problem is intractable except in the simplest of problems; e.g. for a quadratic or a Lipschitz-smooth \(f\) more generally.

Lipschitz continuity:

There exists \(L > 0\) such that for every \(x,y\) the following inequality holds:

\[ \|f(x) - f(y)\| \le L \|x - y\|. \]

This is a statement about how large derivatives can become and defines a global property of a function. To see this, rearrange:

\[ \frac{\|f(x) - f(y)\|}{\|x - y\|} \le L \]

Lipschitz smoothness:

Same as above, except the statement is about gradients of functions.

\[ \|\nabla f(\boldsymbol{x}) - f(\boldsymbol{y})\| \le L \|\boldsymbol{x} - \boldsymbol{y}\| \]

Backtracking

Exact line searches rarely have closed form solutions. Even when th problem is tractable, it may be expensive to compute the step size exactly.

What is done in practice is a backtracking line search. The idea is simple:

  1. Propose an initial step size \(t \leftarrow 1\).
  2. Apply the (gradient descent) update, \(x \leftarrow x + td\).
  3. Check that a descent condition holds; for example, \(f(x + td) < f(x)\).
    • If the descent condition fails, undo the update and set \(t \leftarrow \alpha t\) for \(\alpha \in (0, 1)\). Go back to Step 2 with the new step size.
  4. Continue with gradient descent.

A common choice for \(\alpha\) is \(\alpha = \frac{1}{2}\). This flavor of backtracking is known as step halving.

Example: Gradient Descent + Backtracking

function rosenbrock(x)
  return (1 - x[1]) ^ 2 + 100 * (x[2] - x[1] ^ 2) ^ 2
end
xs = range(-2, 2, step = 0.1)
ys = range(-1, 3, step = 0.1)
contourf(xs, ys, (x, y) -> log10(1e-6 + rosenbrock([x,y])), color = :plasma, levels = 64, lw = 0)
function gradient_descent(f, x0; maxiter::Int = 10, tol::Real = 1e-3, backtracking::Bool = false, t::Real = 0.1)
  # initialize our workspace
  x = copy(x0)
  ∇f = similar(x)

  # initial function + gradient values
  f_old = f(x)
  ForwardDiff.gradient!(∇f, f, x)

  # start the minimization loop
  not_converged = norm(∇f) > tol
  iter = 0
  while not_converged && iter < maxiter
    iter += 1
    if backtracking
      # try a full step
      t = 1.0
      @. x = x - t * ∇f
      while f(x) >= f_old # backtracking
        @. x = x + t * ∇f
        t = t / 2
        @. x = x - t * ∇f
      end
      f_old = f(x)
    else # fixed step size
      @. x = x - t * ∇f
    end
    # check convergence
    ForwardDiff.gradient!(∇f, f, x)
    not_converged = norm(∇f) > tol
  end
  ForwardDiff.gradient!(∇f, f, x)
  return iter, x, f(x), norm(∇f)
end
gradient_descent(rosenbrock, [1.5, 1.5], maxiter = 10^4, backtracking = false)
gradient_descent(rosenbrock, [1.5, 1.5], maxiter = 10^4, backtracking = true)

Other Descent Conditions

Knowledge of more complex descent conditions can improve convergence behavior of a first-order method. Requires some additional background to understand.

  • Armijo: Defines sufficient decrease.
  • Wolfe: Armijo + curvature condition.

Stochastic Gradient Descent

Problems in modern statistics and machine learning heavily favor stochastic algorithms due to

  1. the problem’s training data being “big”, and
  2. function evaluation (and therefore gradient evalution) being “expensive”.

In this setting, it is enough to approximate gradients with batches of the data. However, this requires that the batches be representative of the full data!

Implementation

  • f(params, data): Assumed to be a function-like object that accepts two arguments: a vector of parameters params and data, given as a Tuple of the form (y, X).
  • x0: Starting estimate.
  • batchfun(): A zero-argument function that returns a random batch from the problem’s training data.
function sgd(f, x0, batchfun; maxiter::Int = 10, tol::Real = 1e-3, batchsize::Int = 10)
  # initialize our workspace
  x = copy(x0)
  ∇f, ∇ftmp = similar(x), similar(x)

  # helper function to evaluate gradient on mini-batch
  # note the variables folded into the function definition
  function eval_gradient!(x, batch)
    fill!(∇f, 0)
    for obs in zip(batch[1], eachrow(batch[2]))
      ForwardDiff.gradient!(∇ftmp, params -> f(params, obs), x)
      @. ∇f += ∇ftmp
    end
    @. ∇f = 1 / batchsize * ∇f
    return ∇f
  end

  # initial batch, function + gradient values
  batch = batchfun(batchsize)
  f_old = f(x, batch)
  eval_gradient!(x, batch)

  # start the minimization loop
  not_converged = norm(∇f) > tol
  iter = 0
  while not_converged && iter < maxiter
    iter += 1
    t = 1 / iter
    @. x = x - t * ∇f

    # check convergence
    eval_gradient!(x, batch)
    not_converged = norm(∇f) > tol

    # update the batch
    not_converged && (batch = batchfun(batchsize))
  end
  eval_gradient!(x, batch)
  return iter, x, f(x, batch), norm(∇f)
end

Example: Linear Regression

function simulate_linreg_problem(n, β0, σ; rng = Random.default_rng())
  X = Matrix{Float64}(undef, n, 2)
  @views begin
    fill!(X[:, 1], 1)
    randn!(rng, X[:, 2])
    X[:, 2] .= X[:, 2]
  end
  y = X * β0 .+ σ * randn(rng, n)
  return y, X
end

Step 1: Define the Loss

Remember that ForwarDiff asks that the functions we differentiate only have one argument. If we have multiple parameters, they must be packed into a Vector.

With this in mind, let’s make the coefficients b the first argument below.

function linreg_loss(b, y, X::AbstractMatrix)
  r = y - X*b
  return 1/2 * mean(abs2, r)
end

linreg_loss(b, y, x::AbstractVector) = 1/2 * (y - dot(x, b)) ^ 2
linreg_loss([0.0, 0.0], y, X) # make sure it works!
linreg_loss([0.5, -3.0], y, X)

For compatibility with ForwardDiff, we just use an anonymous function

ForwardDiff.gradient(b -> linreg_loss(b, y, X), zeros(2))

Step 2: Define the Sampling Procedure

Let’s use a batch of fixed size. The following function explicitly requires 3 arguments to sample from (y, X).

function mybatchfun(y, X, batchsize)
  idx = rand(1:length(y), batchsize)
  return y[idx], X[idx, :]
end
yb, Xb = mybatchfun(y, X, 10)
display(yb)
display(Xb)

Other possible schemes:

  • Sample a single observation
  • Cyclic: Shuffle data, then iterate over data using a fixed sized window.

Step 3: Ensure compatibility

To make the output of batchfun() compatible with our loss function, add a method that expands the second argument to y and X.

linreg_loss(b, data::Tuple) = linreg_loss(b, data[1], data[2])

Make sure it works:

linreg_loss(zeros(2), mybatchfun(y, X, 10))

Need compatibility with ForwardDiff.gradient(), too:

abatch = mybatchfun(y, X, 10)
ForwardDiff.gradient(y -> linreg_loss(y, abatch), zeros(2))
