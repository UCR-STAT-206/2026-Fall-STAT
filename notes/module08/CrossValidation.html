Motivation

Many models, particularly in statistical learning, are subject to some form or regularization. Regularization can take the form of a penalty function, which acts as a soft constraint on a model, or explicitly a hard constraint, which often results in a constrained optimization problem. The need for regularization in estimation indeed always results from some type of need:

  • The problem has a poor condition number that makes estimation numerically challenging and/or sensitive to perturbations.
  • We want to avoid the problem of overfitting.
  • We want to select the most parsimonious model possible.
  • We are working in an underdetermined setting (more predictors than data) and need to make estimation unique (identifiability).
  • We want our estimator to have certain qualitative properties.

Choosing regularization often introduces a model selection problem. In some cases, this can be resolved by exploring different models and/or tuning any hyperparameters. This is where cross validation comes in.

Our goal is to maximize or minimize some criterion (e.g. classification accuracy, mean squared error, parsimony + predictive power, …) in a data-driven manner. This amounts to using some of our data to empirically estimate the criterion

\[ \mathrm{CV}(\mathcal{T}) = \frac{1}{|\mathcal{T}|} \sum_{i \in \mathcal{T}} \text{Criterion}(X_{i}, Y_{i}, \ldots), \]

where \(\mathcal{T}\) is a set of indices defining a test set. Unfortunately, we usually also need data to fit a model. Although it is valid to design training and test sets by hand to illustrate a particular point, the simple splitting approach is liable to over/under-estimate the criterion of interest. Resampling can help mitigate this defect.

Running Example

We’ll look at the Least Absolute Shrinkage and Selection Operator (LASSO) in the context of regression

\[ \min_{\beta}~\sum_{i=1}^{n} \left(y_{i} - \sum_{j=0}^p x_{ij} \beta_{j}\right)^{2} + \lambda \sum_{j=1}^{p} |\beta_{j}|. \]

  • The LHS of the expression is the usual sum of squared residuals.
  • The RHS is a penalty based on the \(\|\cdot\|_{1}\) norm, not applied to the intercept.
  • The parameter \(\lambda\) controls the strength of the penaly. Large \(\lambda\) forces the absolute values of coefficients to be small.

A popular algorithm for implementing the lasso is coordinate descent. It is derived through partial optimization, that is, looking at one parameter at a time.

\[ \beta_{k}^{(t+1)} \leftarrow \underset{\beta_{k}}{\mathrm{argmin}} ~\sum_{i=1}^{n} \left(y_{i} - \sum_{j \neq k}^{p} x_{ij} \beta_{j}^{(t)} - x_{ik} \beta_{k}\right)^{2} + \lambda \sum_{j>0,j\neq k} |\beta_{j}^{(t)}| + \lambda |\beta_{k}|. \]

The theory of convex optimization, specifically proximal operators yields a simple update formula even though the absolute value function is not differentiable. Letting \(\boldsymbol{X}_{j}\) denote the \(j\)-th column of \(\boldsymbol{X}\) and \(\boldsymbol{r}^{(t)}\) the residual at iteration \(t\), define the quantity

\[ \rho_{k}^{(t)} = \frac{\boldsymbol{X}_{k}^{\top}\boldsymbol{r}^{(t)}}{\|\boldsymbol{X}_{k}\|^{2}} + \beta_{j}^{(t)} \]

\[ \beta_{k}^{(t+1)} = \begin{cases} \rho_{k}^{(t)}, & \text{if coefficient $k$ is penalized} \\ S_{\lambda \|\boldsymbol{X}_{j}\|^{-2}}(\rho_{k}^{(t)}), & \text{otherwise}. \end{cases} \]

function soft_threshold(x, λ)
  return sign(x) * max(zero(x), abs(x) - λ)
end

function coordinate_descent(y, X, λ; maxiter = 100, tol = 1e-2, intercept = false, verbose = false)
  n, p = size(X)
  β = ones(p)     # intercept + coefficients
  r = zeros(n)    # workspace for residuals
  mul!(r, X, β)   # initial estimate of residuals
  @. r = y - r
  loss(r, β, λ) = @views 0.5 * dot(r, r) + λ * norm(β[(1+intercept):end], 1)
  loss_prev = loss(r, β, λ)
  for iter in 1:maxiter
    if verbose
      @show iter, loss_prev
    end
    # cycle through each coordinate
    for j in 1:p
      # compute |Xⱼ|²
      Xⱼ = view(X, :, j)
      c = dot(Xⱼ, Xⱼ)

      # save old cofficient; needed for updating residual
      βⱼ = β[j]

      # form partial gradient
      rho = dot(Xⱼ, r) / c + β[j]
      if intercept && j == 1
        β[j] = rho
      else
        β[j] = soft_threshold(rho, λ / c)
      end
      
      # update residual remove old contribution from βⱼ and add the new one in
      @. r = r + (βⱼ - β[j]) * Xⱼ
    end
    loss_curr = loss(r, β, λ)
    if abs(loss_curr - loss_prev) < (1 + abs(loss_prev)) * tol
      break
    end
    loss_prev = loss_curr
  end
  return β
end

We’ll use the following to score models. It is simply the penalized objective function.

score_loss(y::Vector, X::Matrix, β, λ, intercept) = 0.5*sum(abs2, y - X*β) + λ * norm(β[(1+intercept):end], 1)
score_loss(y::Number, X::Vector, β, λ, intercept) = 0.5*(y - dot(X,β))^2 + λ * norm(β[(1+intercept):end], 1)

Validation Approach

  1. Randomly split data into a training set to build your model, and a holdout set to validate the fitted model.
  2. Carry out the estimation procedure using the training set.
  3. Evalute the model’s performance using the holdout set.
function train_test_split(y, X, at)
  n = length(y)
  idx = randperm(n)       # "shuffle" the data
  i = round(Int, n * at)  # split at this index
  train = (y[idx[1:i]], X[idx[1:i], :])
  test = (y[idx[i+1:end]], X[idx[i+1:end], :])
  return train, test
end
function validate(y, X, λgrid, score; intercept = false, at = 0.5, kwargs...)
  score_vals = zeros(length(λgrid))
  (y_train, X_train), (y_test, X_test) = train_test_split(y, X, at)
  for (k, λ) in enumerate(λgrid)
    βλ = coordinate_descent(y_train, X_train, λ; intercept = intercept, kwargs...)
    score_vals[k] += score(y_test, X_test, βλ, λ, intercept)
  end
  # identify the 'best' model
  idx = argmin(score_vals)
  λ, best_score = λgrid[idx], score_vals[idx]
  return λ, best_score
end
λgrid = 10 .^ range(-3, 3, step = 0.5)
validate(y, X, λgrid, score_loss; at = 0.5)

Leave-One-Out

  1. Starting from \(i = 1\), use exclude \((x_{i}, y_{i})\) from your data.
  2. Use the remaining \(n-1\) data points to fit your model.
  3. Evaluate the model on the holdout data \((x_{i}, y_{i})\)
  4. Increment \(i\), select the next \((x_{i}, y_{i})\), and go back to Step 2.
function loocv(y, X, λgrid, score; intercept = false, kwargs...)
  idx = ones(Bool, length(y))
  score_vals = zeros(length(λgrid))
  for i in eachindex(y)
    # exclude the i-th datum
    idx[i] = false
    y_train, X_train = @views y[idx], X[idx, :]

    # evaluate models with training set
    for (k, λ) in enumerate(λgrid)
      βλ = coordinate_descent(y_train, X_train, λ; intercept = intercept, kwargs...)
      score_vals[k] += score(y[i], X[i, :], βλ, λ, intercept) / n # averaging score over all LOOCV holdout sets
    end
    idx[i] = true
  end
  # identify the 'best' model
  idx = argmin(score_vals)
  λ, best_score = λgrid[idx], score_vals[idx]
  return λ, best_score
end
λgrid = 10 .^ range(-3, 3, step = 1.0)
loocv(y, X, λgrid, score_loss)

\(K\)-Fold

Generalizes the leave-one-out approach; it is a special case of \(K\)-fold with \(K = 1\).

  1. Randomly split the data into \(K\) groups of roughly equal sizes called a fold.
  2. Reserve the first fold for validation.
  3. Fit the data on the remaining \(K-1\) folds.
  4. Evaluate the model’s performance on the validation set.
  5. Repeat from Step 3 for the next fold until all \(K\) are exhausted.
function kfoldcv(y, X, λgrid, score; K = 5, intercept = false, kwargs...)
  n = length(y)
  idx = round.(Int, range(1, n, K+1)) # indices for computing folds
  score_vals = zeros(length(λgrid))
  for fold in 1:K
    idxval = idx[fold]:idx[fold+1]
    idxtrain = setdiff(1:n, idxval)
    y_train, X_train = y[idxtrain], X[idxtrain, :]
    y_test, X_test = y[idxval], X[idxval, :]
    # evaluate models with training set
    for (k, λ) in enumerate(λgrid)
      βλ = coordinate_descent(y_train, X_train, λ; intercept = intercept, kwargs...)
      score_vals[k] += score(y_test, X_test, βλ, λ, intercept) / K
    end
  end
  # identify the 'best' model
  idx = argmin(score_vals)
  λ, best_score = λgrid[idx], score_vals[idx]
  return λ, best_score
end
λgrid = 10 .^ range(-3, 3, step = 1.0)
kfoldcv(y, X, λgrid, score_loss; K = 5)

The \(K\)-fold strategy tends to have smaller variance compared to Leave-One-Out. Why?

  • Leave-One-Out effectively fits \(n\) models which see nearly identical training data.
  • As such, any model errors/scores will tend to be highly correlated. Estimated metrics are thus highly variable.
  • \(K\)-fold approach only fits \(K\) models which are fit on slightly overlapping data, decreasing correlation.
  • Unfortunately, \(K\)-fold still pays a price: higher bias. Cross validation techniqes are generally subject to bias-variance tradeoffs.

Nested / Repeated

  1. Split data into training and testing.
  2. Further split the training data into actual training and validation; e.g. using \(K\)-fold.
  3. Select the best model using the validation set.
  4. Evaluate the model on the testing set.
  • Should ameloriate the bias-variance tradeoff phenomenon, since the test set is never used for training (weaker correlation to training data).
  • More computationally expensive.

Can repeat any cross validation procedure in a Monte Carlo fashion to aid in assessing stability; e.g. in model selection or hyperparameter tuning.
