BLAS/LAPACK

Introduction

Topics in numerical linear algebra:

  • solve linear equations \(\mathbf{A} \mathbf{x} = \mathbf{b}\)
  • regression computations \(\mathbf{X}^T \mathbf{X} \beta = \mathbf{X}^T \mathbf{y}\)
  • eigen-problems \(\mathbf{A} \mathbf{x} = \lambda \mathbf{x}\)
  • generalized eigen-problems \(\mathbf{A} \mathbf{x} = \lambda \mathbf{B} \mathbf{x}\)
  • singular value decompositions \(\mathbf{A} = \mathbf{U} \Sigma \mathbf{V}^T\)
  • iterative methods for numerical linear algebra

Except for the iterative methods, most of these numerical linear algebra tasks are implemented in the BLAS and LAPACK libraries. They form the building blocks of most statistical computing tasks (optimization, MCMC).

All high-level languages (Julia, Matlab, Python, R) call BLAS and LAPACK for numerical linear algebra. Julia offers more flexibility by exposing interfaces to many BLAS/LAPACK subroutines directly. See documentation.

Memory Allocation

Computers must allocate memory to represent different objects. Depending on the specific dynamic programming language, the amount of memory may be known ahead of time and predictably managed with little overhead. In other instances, the amount of memory is unpredictable based on information within the language and can only be determined once a program is run. We distinguish between these concepts as follows:

  • Static Memory Allocation: This memory is predictable and determined by information encoded within the language. Tuple, StaticArray, type-stable scalar variables, and other objects are usually allocated statically. Sometimes said to “live on the stack”.
  • Dynamic Memory Allocation: This memory cannot be completely determined by information encoded within the language. Array, Dict, and type-unstable quantities are usually allocated dynamically; e.g. when a program is actually run. Sometimes siad to “live on the heap”.

BLAS & LAPACK

BLAS stands for basic linear algebra subprograms.

Basic Linear Algebra Subprograms (BLAS)

  • Netlib provides a reference implementation defining the required tasks and their interfaces.
  • Mathematical Kernel Libraries (MKL)
    • The default for MATLAB.
    • Works on Windows, MacOS, Linux.
    • Proprietary; guaranteed to work on Intel hardware only. Mixed results on AMD, but it appears the situation has improved as of 2022 as reported by Agner Fog.
  • OpenBLAS
    • Free, open source, and cross-platform.
    • Default in R (except Apple silicon).
  • Accelerate
    • BLAS information; support in iOS and iPadOS.
    • Default in R for Apple silicon (at least later versions).
    • Contains additional libraries (including LAPACK).

LAPACK has many important routines for solving linear systems: solving eigenvalue problems, matrix decomposition/factorizations, singular value problems, estimating condition numbers.

Organization

There are 3 levels of BLAS functions.

  • Level 1: vector-vector operation
  • Level 2: matrix-vector operation
  • Level 3: matrix-matrix operation

There is support for various fields and precisions:

  • S single precision
  • D double precision
  • C complex
  • Z double complex

See Netlib’s quick-reference for a comprehensive list.

Level Example Operation Name Dimension Flops
1 \(\alpha \gets \mathbf{x}^T \mathbf{y}\) dot product \(\mathbf{x}, \mathbf{y} \in \mathbb{R}^n\) \(2n\)
1 \(\mathbf{y} \gets \mathbf{y} + \alpha \mathbf{x}\) axpy \(\alpha \in \mathbb{R}\), \(\mathbf{x}, \mathbf{y} \in \mathbb{R}^n\) \(2n\)
2 \(\mathbf{y} \gets \mathbf{y} + \mathbf{A} \mathbf{x}\) gaxpy \(\mathbf{A} \in \mathbb{R}^{m \times n}\), \(\mathbf{x} \in \mathbb{R}^n\), \(\mathbf{y} \in \mathbb{R}^m\) \(2mn\)
2 \(\mathbf{A} \gets \mathbf{A} + \mathbf{y} \mathbf{x}^T\) rank one update \(\mathbf{A} \in \mathbb{R}^{m \times n}\), \(\mathbf{x} \in \mathbb{R}^n\), \(\mathbf{y} \in \mathbb{R}^m\) \(2mn\)
3 \(\mathbf{C} \gets \mathbf{C} + \mathbf{A} \mathbf{B}\) matrix multiplication \(\mathbf{A} \in \mathbb{R}^{m \times p}\), \(\mathbf{B} \in \mathbb{R}^{p \times n}\), \(\mathbf{C} \in \mathbb{R}^{m \times n}\) \(2mnp\)

These operations allow for evaluating and accumulating results of certain operations.

… Theoretically, matrix-matrix multiplication uses O(N^3) operations on O(N^2) data, so there is lots of opportunity for data reuse, meaning that you can get lots of cache and register reuse and therefore a very efficient algorithm. In fact, GEMM (General Matrix Multiply) is just about the only algorithm that gets close to peak performance of modern processors. …

— Victor Eijkhout replying to a Quora question

Examples

The form of a mathematical expression and the way the expression should be evaluated in actual practice may be quite different.

Some operations appear as level-3 but indeed are level-2.

Example 1

A common operation in statistics is column scaling or row scaling

\[ \begin{eqnarray*} \mathbf{A} &=& \mathbf{A} \mathbf{D} \quad \text{(column scaling)} \\ \mathbf{A} &=& \mathbf{D} \mathbf{A} \quad \text{(row scaling)}, \end{eqnarray*} \] where \(\mathbf{D}\) is diagonal. For example, in generalized linear models (GLMs), the Fisher information matrix takes the form
\[ \mathbf{X}^T \mathbf{W} \mathbf{X}, \] where \(\mathbf{W}\) is a diagonal matrix with observation weights on diagonal.

Column and row scalings are essentially level-2 operations!

Random.seed!(206) # seed
n = 2000
A = rand(n, n) # n-by-n matrix
d = rand(n)  # n vector
D = Diagonal(d) # diagonal matrix with d as diagonal
Dfull = diagm(d) # convert to full matrix
# this is calling BLAS routine for matrix multiplication: O(n^3) flops
# this is SLOW!
@benchmark $A * $Dfull
# dispatch to special method for diagonal matrix multiplication.
# columnwise scaling: O(n^2) flops
@benchmark $A * $D
# Or we can use broadcasting (with recycling)
@benchmark $A .* transpose($d)
# in-place: avoid allocate space for result
# rmul!: compute matrix-matrix product A*B, overwriting A, and return the result.
@benchmark rmul!($A, $D)
# In-place broadcasting 
@benchmark $A .= $A .* transpose($d)
Note

In R or Matlab, diag(d) will create a full matrix. Be cautious using diag function: do we really need a full diagonal matrix?

d <- runif(5)
diag(d)

This works only when Matlab is installed.

#| eval: false
using MATLAB

mat"""
d = rand(5, 1)
diag(d)

Example 2

The inner product between two matrices \(\mathbf{A}, \mathbf{B} \in \mathbb{R}^{m \times n}\) is often written as

\[ \text{trace}(\mathbf{A}^T \mathbf{B}), \text{trace}(\mathbf{B} \mathbf{A}^T), \text{trace}(\mathbf{A} \mathbf{B}^T), \text{ or } \text{trace}(\mathbf{B}^T \mathbf{A}). \] They appear as level-3 operation (matrix multiplication with \(O(m^2n)\) or \(O(mn^2)\) flops).

Random.seed!(123)
n = 2000
A, B = randn(n, n), randn(n, n)

# slow way to evaluate tr(A'B): 2mn^2 flops
@benchmark tr(transpose($A) * $B)

But \(\text{trace}(\mathbf{A}^T \mathbf{B}) = \langle\text{vec}(\mathbf{A}), \text{vec}(\mathbf{B})\rangle\). The latter is level-1 BLAS operation with \(O(mn)\) flops.

# smarter way to evaluate tr(A'B): 2mn flops
@benchmark dot($A, $B)

Example 3

Similarly \(\text{diag}(\mathbf{A}^T \mathbf{B})\) can be calculated in \(O(mn)\) flops.

# slow way to evaluate diag(A'B): O(n^3)
@benchmark diag(transpose($A) * $B)
# smarter way to evaluate diag(A'B): O(n^2)
@benchmark Diagonal(vec(sum($A .* $B, dims = 1)))

To get rid of allocations for intermediate arrays we can just write a double loop or use the dot() function.

function diag_matmul!(d, A, B)
    m, n = size(A)
    @assert size(B) == (m, n) "A and B should have same size"
    fill!(d, 0)
    for j in 1:n, i in 1:m
        d[j] += A[i, j] * B[i, j]
    end
    Diagonal(d)
end

d = zeros(eltype(A), size(A, 2))
@benchmark diag_matmul!($d, $A, $B)

Memory hierarchy and level-3 fraction

Effective use of memory hierarchy is key to high performance. This is true on all architectures.

Unfortunately, flop counts does not tell the full story. Another important factor is data movement through the memory hierarchy.

Source: https://cs.brown.edu/courses/csci1310/2020/assign/labs/lab4.html

In Julia, we can query the CPU topology by the Hwloc.jl package.

# from Hwloc package
topology_graphical()
  • Example: Intel Xeon X5650 CPU has a theoretical throughput of 128 double-precision Gigaflops (GFlops) but a maximum memory bandwidth of 32GB/s.
  • Can we keep CPU cores busy with enough deliveries of matrix data and ship the results to memory fast enough to avoid backlog? Only if we can use high-level BLAS!
  • Higher level BLAS (3 or 2) make more effective use of arithmetic logic units (ALU) by keeping them busy. Surface-to-volume effect.
BLAS Dimension Mem. Refs. Flops Ratio
Level 1: \(\mathbf{y} \gets \mathbf{y} + \alpha \mathbf{x}\) \(\mathbf{x}, \mathbf{y} \in \mathbb{R}^n\) \(3n\) \(2n\) 3:2
Level 2: \(\mathbf{y} \gets \mathbf{y} + \mathbf{A} \mathbf{x}\) \(\mathbf{x}, \mathbf{y} \in \mathbb{R}^n\), \(\mathbf{A} \in \mathbb{R}^{n \times n}\) \(n^2\) \(2n^2\) 1:2
Level 3: \(\mathbf{C} \gets \mathbf{C} + \mathbf{A} \mathbf{B}\) \(\mathbf{A}, \mathbf{B}, \mathbf{C} \in\mathbb{R}^{n \times n}\) \(4n^2\) \(2n^3\) 2:n

Source: Jack Dongarra’s slides.

  • A distinction between LAPACK and LINPACK (older version of R uses LINPACK) is that LAPACK makes use of higher level BLAS as much as possible (usually by smart partitioning) to increase the so-called level-3 fraction (ratio of data access operations to flops in level-3 algorithms).
  • To appreciate the efforts in an optimized BLAS implementation such as OpenBLAS (evolved from GotoBLAS), see this video. Respecting memory layout

Both R and Julia implement a column-major ordering of matrix data. This means columns represent contiguous chunks of memory which are easy to pack into caches.

Whenever possible, you should access data in the format preferred by your computing language. We demonstrate this with matrix multplication:

\[ \mathbf{C} \leftarrow \mathbf{C} + \mathbf{A}\mathbf{B} \qquad \mathbf{A} \in \mathbb{R}^{m \times p}, \mathbf{B} \in \mathbb{R}^{p \times n}, \mathbf{C} \in \mathbb{R}^{m \times n}. \]

Implementing this operation requires 3 loops. Depending on the data access pattern, there are 6 possible variants:

# jki or kji; inner most loop
for i in 1:m
    C[i, j] = C[i, j] + A[i, k] * B[k, j]
end

# ikj or kij; inner most loop
for j in 1:n
    C[i, j] = C[i, j] + A[i, k] * B[k, j]
end

# ijk or jik; inner most loop        
for k in 1:p
    C[i, j] = C[i, j] + A[i, k] * B[k, j]
end

The following code implements fast (but not BLAS-fast) algorithms for matrix multiplication:

"""
    matmul_by_loop!(A, B, C, order)

Overwrite `C` by `A * B`. `order` indicates the looping order for triple loop.
"""
function matmul_by_loop!(A::Matrix, B::Matrix, C::Matrix, order::String)
    
    m = size(A, 1)
    p = size(A, 2)
    n = size(B, 2)
    fill!(C, 0)
    
    if order == "jki"
        @inbounds for j = 1:n, k = 1:p, i = 1:m
            C[i, j] += A[i, k] * B[k, j]
        end
    end

    if order == "kji"
        @inbounds for k = 1:p, j = 1:n, i = 1:m
            C[i, j] += A[i, k] * B[k, j]
        end
    end
    
    if order == "ikj"
        @inbounds for i = 1:m, k = 1:p, j = 1:n
            C[i, j] += A[i, k] * B[k, j]
        end
    end

    if order == "kij"
        @inbounds for k = 1:p, i = 1:m, j = 1:n
            C[i, j] += A[i, k] * B[k, j]
        end
    end
    
    if order == "ijk"
        @inbounds for i = 1:m, j = 1:n, k = 1:p
            C[i, j] += A[i, k] * B[k, j]
        end
    end
    
    if order == "jik"
        @inbounds for j = 1:n, i = 1:m, k = 1:p
            C[i, j] += A[i, k] * B[k, j]
        end
    end
    
end

Random.seed!(123)
m, p, n = 2000, 100, 2000
A = rand(m, p)
B = rand(p, n)
C = zeros(m, n);
@benchmark matmul_by_loop!($A, $B, $C, "jki") # best
@benchmark matmul_by_loop!($A, $B, $C, "kji") # second best
@benchmark matmul_by_loop!($A, $B, $C, "ikj")
# dispatches to BLAS
@benchmark mul!($C, $A, $B)
# call BLAS directly
@benchmark LinearAlgebra.BLAS.gemm!('N', 'N', 1.0, $A, $B, 0.0, $C)

BLAS in R

Tip for R users. Standard R distribution from CRAN uses a very out-dated BLAS/LAPACK library.

# R code via RCall
sessionInfo()
library(bench)
A <- $A
B <- $B
bench::mark(A %*% B) |>
  print(width = Inf)

Re-building R from source using OpenBLAS or MKL will immediately boost linear algebra performance in R. Google build R using MKL to get started.

Avoiding Memory Allocation

Transpose is an expensive memory operation

In R, the command

t(A) %*% x

will first transpose A then perform matrix multiplication, causing unnecessary memory allocation

Random.seed!(123)

n = 1000
A = rand(n, n)
x = rand(n);
R"""
A <- $A
x <- $x
bench::mark(t(A) %*% x) |>
  print(width = Inf)
""";

Julia is avoids transposing matrix whenever possible. The Transpose type only creates a view of the transpose of matrix data.

typeof(transpose(A))
fieldnames(typeof(transpose(A)))
# same data in tranpose(A) and original matrix A
pointer(transpose(A).parent), pointer(A)
# dispatch to BLAS
# does *not* actually transpose the matrix
@benchmark transpose($A) * $x
# pre-allocate result
out = zeros(size(A, 2))
@benchmark mul!($out, transpose($A), $x)
# or call BLAS wrapper directly
@benchmark LinearAlgebra.BLAS.gemv!('T', 1.0, $A, $x, 0.0, $out)

Broadcast (dot operation) fuses loops and avoids memory allocation

Broadcasting in Julia achieves vectorized code without creating intermediate arrays.

Suppose we want to calculate elementsize maximum of absolute values of two large arrays. In R or Matlab, the command

max(abs(X), abs(Y))

will create two intermediate arrays and then one result array.

Random.seed!(123)
X, Y = rand(1000, 1000), rand(1000, 1000)

R"""
library(bench)
bench::mark(max(abs($X), abs($Y))) |>
  print(width = Inf)
""";

In Julia, dot operations are fused so no intermediate arrays are created.

# no intermediate arrays created, only result array created
@benchmark max.(abs.($X), abs.($Y))

Pre-allocating result array gets rid of memory allocation at all.

# no memory allocation at all!
Z = zeros(size(X)) # zero matrix of same size as X
@benchmark $Z .= max.(abs.($X), abs.($Y)) # .= (vs =) is important!

Views

View avoids creating extra copy of matrix data.

Random.seed!(123)
A = randn(1000, 1000)

# sum entries in a sub-matrix
@benchmark sum($A[1:2:500, 1:2:500])
# view avoids creating a separate sub-matrix
@benchmark sum(@view $A[1:2:500, 1:2:500])

The @views macro can be useful in some operations.

@benchmark @views sum($A[1:2:500, 1:2:500])

Pre-Allocation Pattern

Pre-allocating buffers for intermediate quantities or outputs can significantly impact performance (but not always!). As such, it is common to see Julia functions for out-of-place and in-place implementations.

  • Out-of-Place: Implementation has allocations for output. Usually just copies the input in some way.
  • In-Place: Implementation has no allocations for output. Usually mutates the input in some way.
  • Allocation-Free: No allocations whatsover. Type-stable + all required buffers are allocated by the caller.

See for example sort() vs sort!() in Julia.

function f!(output, inputs...)
  # use inputs to carry out algorithm,
  # modifying output in the process
  return output
end

function f(inputs...)
  output = allocate_the_output()
  f!(output, inputs...)
end

Takeaway

Use good algorithms and reuse data wherever possible!

  1. When possible, frame your problem in terms of linear algebra and specifically high-level BLAS operations.
  2. Good code should be mindful about algorithms; this means having some understanding of complexity and interactions with hardware.
  3. In Julia: we can work very low level (e.g. BLAS.gemm(...)), high level (e.g. C = A*B), or somewhere in between (e.g. mul!(C, A, B)).
  4. In R: No direct control over memory, have to trust the language. We can still be mindful about memory usage; e.g. reuse data and avoid allocations like t(X) whenever possible.

These principles apply to both statistical computing and high-level data analysis.
