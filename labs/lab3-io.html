Lab 3: I/O Handling

Published

October 16, 2026

Goals

By the end of this lab, you should

  1. have an understanding of text versus binary files,
  2. be able to distinguish between flat versus hierarchical file types, and
  3. be able to load numeric data using DelimitedFiles.jl or CSV.jl.

Data storage formats

  • Files on a computer can be categorized as text files or binary files. Both file types are encoded as bit patterns.
  • Text files encode individual characters, allowing text editor programs to easily display the contents of a file to a user.
    • Examples: CSV (.csv), TSV (.tsv), HTML (.html), XML (.xml), JSON (.json)
    • Often has a specific standard defining how these files are formatted; for example valid CSV files should adhere to RFC 41800.
    • Internal markup language/syntax is fairly simple.
    • Usually, but not always, related to storing a dataset in the sense that is familiar to statisticians/data scientists.
  • Binary files have their contents encoded in a (sometimes proprietary) specialized format. These types of files are typically not meant to be manipulated by text editors, and instead use their specialized representation to minimize file size or enhance performance in certain workflows.
    • Examples: R data (.Rda and similar file types), Arrow (.arrow), Parquet (.parquet), Python’s Pickle format (.pkl or .pickle), HDF5 (.hdf5), JLD2 (.jld2).
    • Who knows how the contents are stored… it does not matter for the intended use.
    • Often, but not always, related to the idea of serializing objects in a programming language so they can be reused across sessions.

Text file types

Flat text files

Flat text files are straightforward. Other than relying on a few special characters to separate distinct items, the textual representation you see exactly defines the data.

  • Common format for tabular data: 1 row = 1 observation and 1 column = 1 variable, field, or parameter.
  • Might rely on fixed width format in which each value must be encoded as text of a certain length.
  • Might rely on a delimiter to separate distinct values.

One annoying quirk: Windows and Linux-like systems use different line endings!

  • Line endings typically handled by invisible ASCII characters.
  • If you create a file on Windows: newline \n and carriage return \r.
  • If you create a file on MacOS/UNIX/Linux: only newline \n.

Hierarchical text files

Some text files rely on a hierarchical structure defined by an elaborate markup language. A classic example is HTML:

  • Usually starts with <!DOCTYPE html> as a document type declaration (if adhering to W3C standards).
  • Followed by an opening <html> tag…
  • Followed by a nested <head></head> section…
  • Followed by a nested <body></body>…
  • And finally closed out by an </html> tag.

We can edit these by hand, but its best to use a specialized editor to parse and edit, whenever possible.

How to read and write

Streams

Julia’s support for powerful abstraction makes it so you can get by only knowing about the open() command \(\pm\) 1 or 2 additional tools. Specifically, the patterns you should commit to memory are:

# to read a file
open("path/to/file", "r") do io
  # do something with the IO stream
end
# to (over)write to a file
open("path/to/file", "w") do io
  # do something with the IO stream
end

In both instances, you are manipulating an IOStream object that handles the logic of reading and writing the contents of a file. The patterns above ensure you always close out the underlying stream. There are many convenience functions like read(), readlines(), and write() that you might also find helpful.

You’ve already been working with streams:

  • stdout, the standard output stream. This is used to handle the logic of displaying information to you when you run commands in the Julia REPL.
  • stdin, the standard input stream. This is used to handle the logic of reading and parsing commands you enter in the Julia REPL.

The following focuses on the DelimitedFiles.jl and CSV.jl packages.

Alternatively, we can use the combination of CSV.jl with Tables.jl to parse and import the data as a Matrix{Float64}:

using CSV, Tables
mydata = CSV.read("../hw/assets/nnmf-2429-by-361-face.txt", Tables.matrix; header = false)
  • Tables.jl: provides a specification for what “tabular data” means. The CSV.jl package uses it to some extent.
  • CSV.jl: handles parsing a CSV file based on a careful definition of how these files are defined. Will work with other delimiters like tabs, \t, pipes |, and so on.
  • Both of these packages have too many features to list here.

How to write a file

Using DelimitedFiles.jl:

using DelimitedFiles, Images

myitem = mydata[:, 1]
writedlm("whatisthis.txt", myitem, ' ')

Using CSV.jl + Tables.jl:

using CSV, Tables

myitem = mydata[:, 1]
CSV.write("whatisthis.txt", Tables.table(myitem), delim = ' ', header=false)
  • CSV expects the object to be saved to generate “rows”. Since a Vector{Float64} iterates Float64 values, CSV.jl will complain that your object is not a table.
  • Wrap it in Tables.table() to specify a table-like structure. You use it to add a header.

Handling file paths

Earlier you encountered the relative file path "../hw/assets/nnmf-2429-by-361-face.txt". This is bad because Windows and Linux-like systems use different file path separators. The better, robust alternative is to use joinpath() to form paths:

joinpath("..", "hw", "assets", "nnmf-2429-by-361-face.txt")
"../hw/assets/nnmf-2429-by-361-face.txt"

This will \(\text{Do The Right Thing}^{\text{TM}}\) depending on the underlying operating system.
