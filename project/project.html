Final Project

Wednesday, December 9

Overview

Working in teams of 2 to 4 students, students will plan, implement, and prepare a report on an original computational project in statistics. The primary task is to implement and experiment with your own Julia package. Student projects must extend beyond the application of existing software, methods, or data analysis.

Guidelines and expectations

  • Teams will be assigned. Exceptions to this rule are exceedingly rare.
  • The final project should not be a huge undertaking. It should be relatively easy to complete if your team works together. Pick a well-defined, achievable project.
  • Your work does not need to be novel, but it must represent your own ideas and effort. Translating existing software from one language to Julia, writing a wrapper package for an existing tool, or reproducing published work is not sufficient for a successful project. Your project should push beyond what others have done, even if it is incremental.
  • Your project must be implemented in Julia as a Julia package, complete with documentation and instructions. Any numerical experiments or benchmarks must be reproducible.
    • I am open to making exceptions to the Julia language rule, but students should be prepared to make a strong case on why the project must use another programming language.
    • You are allowed to use other languages for support. For example, data pre-processing or figure preparation. That said, be mindful that adding other languages to a project sometimes has the effect of making reproducibility slightly more challenging.
  • Projects must use Git for version control.
  • Reports must be prepared using Quarto.
  • Your report must contain a quantitative deliverable.
    • This is to discourage reports that merely contain figures with little meaningful analysis.

Project ideas

  1. Implement an algorithm or method related to statistical computing from scratch.
  2. Replicate a published study by implementing any required methods and identifying/using appropriate data sets.
    • Start with reproducing the original work.
    • If your replication study involves little programming, then you will be asked to make a strong case for why your idea is an appropriate computational project.
  3. Design a visualization tool for a type of data you are familiar with, taking great care to ensure nuances is quantitative interpretation are conveyed appropriately.
    • Use a recipe system (either in Makie.jl or Plots.jl) to implement the visualization.
    • Think carefully about the user interface: What are the main inputs and outputs?
    • Think carefully about the design itself: How does each distinct visual element contribute to strong, visual communication of a statistical or quantitative concept?

See the handout on Canvas for specific papers or software packages you might consider for inspiration.

Deadlines

Thursday, November 12: Submit a project description on Canvas

  • Motivate the problem you are working on: Why do people care about the problem, and what aspect of it is challenging from a computational standpoint?
  • Summarize the methods/tools you are working with, and identify any prior art that might be relevant to your project.
  • Provide an outline of the project’s code. The following questions are provided to help you organize your thinking.
    • What are the main functions a user will interact with?
    • Are there any custom classes you anticipate will be needed?
    • Are there any code dependencies (other packages) you might require and need to manage?
    • What are the main tests for your code?
    • What applications or data will you test your code on?

Wednesday, December 9: Project due on GitHub

  • Ensure instructors have access to the project.
  • Repository should include package code and tests.
  • Also include a report prepared with Quarto with the main examples you wish to highlight.
  • Additional details will be provided to you.

Suggested repository structure:

.
├── report
├── src
├── Project.toml
└── README.md
  • report should contain the files to reproduce your report. **Make sure to include a separate Project.toml for any dependencies specific to the examples.
  • src contains your package’s source code.
  • Project.toml records package-level dependencies. Do not include dependencies specific to examples.
  • README.md should be a brief project summary with authors and, ideally, at least one short example illustrating how to use your code.
